### 任务契约

- **目标**：一句话，可验收。
- **入口 / 平台**：用户从哪个页面、命令或接口进入。
- **技术栈 / 复用约束**：用哪些现有包与模式；明确不引入的新依赖。
- **必须支持的交互**：点击 / 输入 / 键盘 / 刷新 / 返回 / 深链。
- **必须覆盖的场景**：正常、边界、失败、权限、并发。
- **明确不做**：本次不碰的范围。
- **完成标准**：3~8 条，每条对应一条可执行命令或可观察行为。
- **计划**：编号步骤 → 每步的验证方式。
- **规格工件（L2）**：proposal → specs/design → tasks（tasks 最后写）。

> 写不出可执行验证方式的完成标准，删掉或改写；不要保留「体验良好」这类无法判定的条目。
